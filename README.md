# aiwork

闲得无聊时，找点想法，让 AI 一起跑起来。

这是一个个人实验仓库，用来借助 AI 探索兴趣、尝试技术、做教学演示，以及验证各种突然冒出来的想法。内容可以很杂：一个小工具、一段模拟、一个小游戏、一份学习材料，或者一个只想看看能不能实现的点子。

这里欢迎半成品、失败的尝试和暂时搁置的实验。能跑出结果、学到一点东西，或者单纯玩得开心，都算有收获。

## 可以做些什么

- **爱好与娱乐**：小游戏、互动作品、趣味数据分析、创意生成。
- **技术探索**：试用新框架、体验新工具、比较实现方案、研究自动化。
- **学习与教学**：把概念做成可运行的例子、可视化演示或练习。
- **日常小工具**：解决一个具体的小麻烦，看看 AI 能帮到哪一步。
- **想法验证**：用最小原型回答“这能做吗？”“这样有没有用？”

题材和技术栈不设限制，按每个实验的需要来选。

## 怎么开始

1. 写下想做什么，以及最想验证的一个问题。
2. 让 AI 帮忙拆解，先做出一个可以运行的最小版本。
3. 实际运行，检查结果是否符合预期。
4. 记下发现、问题和下一步，再决定继续完善还是换个想法。

可以用这样的描述开启一次实验：

> 我想做一个【想法】，主要用来【用途】。先实现【最小功能】，通过【运行方式或检查方法】验证效果。请把代码和说明放在独立目录里，并记录运行结果和局限。

## 项目怎么放

当前仓库尚未包含具体实验，已建立以下基础目录。每个新实验在 `projects/` 下创建自己的目录：

```text
aiwork/
├── README.md
├── LICENSE
├── ideas/              # 随手记下的点子和待验证问题
├── projects/           # 各自独立的小项目和实验
└── notes/              # 学习笔记、复盘和可复用经验
```

每个实验尽量放在独立目录中，自行管理依赖和运行方式。仓库不要求统一语言、框架或启动命令；具体操作以各项目的 README 为准。

一个项目的说明能回答下面几个问题就够了：

- 想做什么，验证什么？
- 需要哪些依赖，怎么运行？
- 实际试了什么，结果如何？
- 有哪些局限，还有什么值得继续试？

## 和 AI 一起做实验

让 AI 帮忙写代码、查思路、解释概念、生成示例，也保留自己的判断。生成出来的东西要实际运行；结论要有对应的检查或证据。暂时没验证的部分就直接标明，失败的结果也值得留下。

尽量让每次尝试小一点，让结果容易观察，让下次接着玩的时候能看懂。
