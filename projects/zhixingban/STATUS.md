## v1.4 日常体验与 Agent

- 新增撤销（当前窗口最近 30 步、文字输入保留原生 Ctrl+Z）和任务/日程回收站；恢复找回进展及仍有效的关联，依赖不引入环。批量安排与排序作为一次操作，可一次撤销。
- 项目「继续上次工作」显示最近结果、当前卡点、可选下一小步和 Obsidian 入口；兼容旧完成记录。今日页可集中整理旧计划，继续今天、改日或暂不安排，不修改截止日期。
- 支持按计划周期/完成后重复、暂停、月末锚点、常用任务模板和可选预计耗时；完成只产生一个未来周期，不制造积压，原结果保留、截止日期不复制。
- 首页两周项目进展条、回顾卡点观察时长、日历七天安排概览来自同一数据，可点击追溯。暂无记录不等于没有工作，完成数量不推算科研价值或目标完成比例。未估时明确显示，参考时长可选。
- 页面切换记住滚动位置；项目选择、归档/地图筛选、日历视图/日期及回顾周记在本机。
- 原则库支持新增、编辑、停用、删除和恢复默认；条件/范围/单位/阈值/建议行动均可改，manual 为文字原则，不自动检查。旧五规则兼容；空原则库不会自动补回。明确保存原则会等待持久化完成后收起编辑器。
- Node 本地服务与界面、CLI、MCP 共用领域命令及校验；正常启动以本机文件为唯一来源。服务仅监听 127.0.0.1，验证 Host/Origin/本机凭据，独占数据目录、串行写入、临时文件替换、版本冲突拒绝覆盖。
- 本地服务每日首次修改前、替换前、每次 Agent 修改前保存完整快照，最多 30 份；界面可下载和恢复。损坏恢复需明确操作，先保留原文件到 recovery/。JSON 导入也识别服务快照/data.json 的封装，内层仍完整校验。
- 旧 IndexedDB 原库保留；仅文件数据尚空时自动迁移。文件已有数据时不自动覆盖，可导出或明确恢复旧浏览器数据。静态网页保留明确的浏览器模式，网络故障不静默切换成另一库。
- CLI/MCP 可查询与维护任务、项目/阶段、日程、进展/检查点、原则、模板、回收站和周记；无需开启浏览器，服务未运行时可自动启动。具体配置与约束见 AGENT_API.md。后台服务可用 stop.cmd 或 npm run stop 停止。
- 启动脚本会按 package-lock 哈希检查依赖更新，避免旧 node_modules 导致升级构建失败。仍每次构建当前源码，服务和网页一起构建。

## 实际限制

- 本地 Node.js 22.12+ 应用，首次/依赖更新需要安装依赖；核心运行不连接云服务。没有 Windows 安装包、跨设备同步、系统通知或整个 Obsidian 库的读写。
- 开发环境为 Linux Chromium；Windows 双击、Edge、Obsidian 协议唤起尚未在真实 Windows 电脑验证。脚本保持固定地址 http://127.0.0.1:5173，升级先停旧服务，并用原浏览器打开完成首次迁移。
- 科学目标由用户确认，Agent 不得编造结果。工作日仅为周一至周五，不计算投入工时或节假日；卡点图的天数为观察时长。历史周回顾中的当前进度/预警明确是当前状态。
- 撤销是当前窗口内的短期历史；外部更新会清掉过期历史。跨重启用回收站和完整快照。浏览器兼容模式的快照仍在浏览器内，需另外导出 JSON。
